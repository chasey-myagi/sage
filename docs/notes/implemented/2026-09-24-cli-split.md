# CLI 壳按职责拆分

## Problem

`apps/sage` 只有两个文件：`main.ts` 1087 行，`bench.ts` 1069 行。`runCli` 149 行，`parseArgs` 128 行，bench 的 `parseRun` 124 行、`runTask` 115 行。旗标清单在 `main.ts` 写了四遍（`FlagName`、`usage`、`flagName`、`inlineFlag`），`bench.ts` 另有一套解析器。`positiveInt` 与三个报错函数、`AUTO_PROVIDERS`、`isRecord` 各复制两份；`"rule" | "model" | "jev"` 手写约十次，`runSage` 的 opts 类型写了三遍；`runTask` 里六个几乎相同的错误返回字面量，`defaultPrepare` 连续五次 `if (code !== 0) throw`。默认预算 `40000` 是裸数字，默认轮数 `80` 在 bench 与内核 `session.ts` 各写一次。`main.ts` 的文件头 79 行，是按 PR 追加的逐旗标清单，还混着 bench 与 stats 的行为。

## Decision

纯重构，行为不变。拆分后的文件地图：

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| `src/main.ts` | 63 | 子命令分派与 `runCli`；直接运行时退出 |
| `src/options.ts` | 276 | 唯一的选项表 `OPTIONS`、基于 `node:util` parseArgs 的分词器 `readFlags`、usage 渲染、共用校验（正整数、网络开关、枚举、ladder）与报错文本、具名值类型 |
| `src/args.ts` | 219 | `sage -p` 的 `parseArgs` 与总 usage |
| `src/print.ts` | 210 | 一次性运行：预检（entry 打分、沙箱、Jev key）、鉴权、adapter 装配、进度行、`session.run` |
| `src/auth.ts` | 146 | `AUTO_PROVIDERS`、`resolveAuth`、bench 的 key 预检、`adaptersFromEnv`、`createAdapter` |
| `src/scorers.ts` | 49 | 按名字构造打分器、`jevApiKey` |
| `src/coding-session.ts` | 258 | `createCodingSession`、`defaultRoutePolicy`、`systemPrompt`、`DEFAULT_BUDGET` |
| `src/stats.ts` | 201 | `sage stats` 与影子对账 `shadowAudit` |
| `src/io.ts` | 44 | `TextOut`、`CommandIo`、`CliIo` |
| `src/guards.ts` | 21 | `isRecord`、`isFiniteNumber`、`assertNever`（apps 内唯一一份） |
| `src/bench/cli.ts` | 29 | `sage bench` 分派 |
| `src/bench/args.ts` | 201 | `bench run` 的参数表子集、`parseRun`、bench usage |
| `src/bench/run.ts` | 193 | `bench run`：key 预检、读任务、运行根目录、逐任务执行、写 `results.json`、遗留目录告警 |
| `src/bench/task.ts` | 171 | 单任务流水线与结果分类、子进程 argv、会话复制 |
| `src/bench/git.ts` | 144 | 单提交拉取 `defaultPrepare`、`CloneUncleanError`、testPatch 恢复与应用 |
| `src/bench/deps.ts` | 77 | 生产环境的 `BenchDeps` 与 sage bin 路径 |
| `src/bench/exec.ts` | 45 | 子进程执行 |
| `src/bench/tasks.ts` | 75 | 任务文件读取与校验 |
| `src/bench/report.ts` | 156 | `bench report` 与 `benchMetrics` |
| `src/bench/types.ts` | 141 | bench 共用类型、`BENCH_WORKSPACE_PREFIX`、`SageRunOptions` |

参数解析用 `node:util` 的 `parseArgs`，`strict: false`、`tokens: true`，再按 token 顺序折叠。旗标只在 `OPTIONS` 写一次，每个命令给出一张「名字 + required/optional/hidden」的列表，同一张列表既决定接受哪些旗标，也按顺序渲染 usage，渲染结果与原 usage 文本逐字相同。严格模式做不到现有行为：`-p --json hi` 里 `-p` 不吃以 `-` 开头的下一个参数、`--budget -5` 要报 usage 而不是抛异常、`--budget abc --nope` 要先报预算错误（按 argv 顺序报第一个错）。所以用非严格模式拿 token，再补四条规则：拒绝分组短旗标与 `-p=x`（token 的 `rawName` 必须等于原参数）、拒绝 `--` 与单独的 `-`、分开写的值不能以 `-` 开头、只有 `--print` 这个布尔旗标接受 `=值`。`-p` 定义为布尔旗标，紧跟其后的位置参数作为任务。

具名常量：`DEFAULT_BUDGET = 40_000` 在 `coding-session.ts`；默认轮数属于内核，`packages/core` 导出 `DEFAULT_MAX_TURNS`，`session.ts` 与 bench 都引用它。类型：`ScorerName`、`ScorerApply`、`BenchPolicy` 由 `as const` 数组派生，`LadderRung`、`SageRunOptions`、`BenchErrorReason` 各定义一次；沙箱入参用 `@sage/tools` 已导出的 `ToolSandbox` 的 `Partial`，不必改 tools。

文件头按 G7 重写，每个不超过 25 行；逐旗标行为全部搬进 `apps/sage/README.md`，并补上原来只写在文件头里的内容：会话装配、`SAGE_SANDBOX_ALLOW_ROOT`、`--scorer rule|model`、`--provider typesafe`、未知预设、`stats` 的错误退出、整段 bench 流程与 `results.json` 字段。

## Alternatives considered

不用严格模式的 `util.parseArgs` 直接解析。它遇到 `-p --json hi`、`--budget -5` 会抛 `ERR_PARSE_ARGS_*`，报错文本与退出码都变，现有测试钉住的正是这些行为。

不手写表驱动解析器。非严格模式的 token 已经给出顺序、`rawName`、`inlineValue`，剩下的四条规则只有十几行；手写一遍分词等于把内置的再实现一次。

不把 bench 的 key 检查并进 `resolveAuth`。两者退出码不同（无 key 时 `sage -p` 退出 1、bench 退出 2），bench 对未知预设在参数阶段就报 usage。只共用 `AUTO_PROVIDERS` 和「缺哪些 key」的报错文本，原来 `sage -p` 写死的那行字符串改为由预设表算出，文本不变。

不在 `main.ts` 转出 `parseArgs`、`createCodingSession` 等给测试用。测试改 import 路径即可，`main.ts` 只留分派。

## Consequences

加旗标改三处：`OPTIONS` 一行、命令列表一行、折叠函数一个分支；usage 自动跟上。`sage -p` 的解析失败现在总带 `exitCode`（usage 错误为 1），原来省略时由 `runCli` 补 1，进程行为不变。

apps 之外只改了 `packages/core/src/session.ts`（新增 `DEFAULT_MAX_TURNS` 并替换 `?? 80`）与 `packages/core/src/index.ts`（导出它）。

测试只改 import 路径：`parseArgs` 从 `src/args.ts`，`createCodingSession`、`defaultRoutePolicy` 从 `src/coding-session.ts`，`adaptersFromEnv` 从 `src/auth.ts`，`defaultPrepare` 从 `src/bench/git.ts`。e2e 里一处动态 import 同时取 `defaultRoutePolicy` 和 `adaptersFromEnv`，拆成两次 import。没有改任何断言。

## Testing

`pnpm check` 退出码 0（lint、tsc、分层、README、log manifest、85 个文件、412 个测试），与拆分前相同。

另用一次性探针对比拆分前后：143 组 argv 覆盖 `parseArgs` 的边界（`-p` 后跟旗标或空串、`-ph`、`-p=x`、`--`、单独的 `-`、`--flag=` 空值、`--budget -5` 与 `--budget=-5`、`--tool-sandbox` 与 `--tool-network` 交替、先后两个错误的报错顺序、布尔旗标带 `=值`），以及 `runCli` 在 `stats`、`bench run`、`bench report` 与 `-p` 预检各路径上的 stdout、stderr 与退出码。除解析结果对象的键顺序和 usage 错误显式带上的 `exitCode: 1` 外，全部一致。

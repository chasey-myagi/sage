# 轮数上限

## Problem

可信版 bench（干净 clone + 断网）两组唯一失败都是 vue-10874：passthrough 在 50 轮自称完成但测试没过，compiler 在 50 轮写下 `outcome: max_turns`。另有 3 条任务跑到 41–47 轮。`AgentSession.run` 默认 `maxTurns` 是 50，`sage` 和 `bench run` 都没有把这个上限露出来。

## Decision

默认 `maxTurns` 改为 80。`sage [-p] --max-turns <n>` 只接受正整数，否则退出 2，stderr 一行点名这个值。合法的数交给 `session.run`，编译器和 `--passthrough` 都生效。

`sage bench run --max-turns <n>` 把同一对参数放进每个任务的 `sage -p` argv，passthrough 也放。没写旗标时 argv 里仍是 `--max-turns 80`。`results.json` 顶层 `maxTurns` 是这个整数：写了旗标用那个数，没写是 80。两种策略都记。`bench report` 的 `a`、`b`、`delta` 不含这个字段。

## Alternatives considered

为什么不保持默认 50、只加旗标。vue-10874 死在没人传参的那次默认上。不改默认，现有的 bench 命令还是 50 轮停。

为什么没写旗标时结果记 80，而不是像 `budget` 那样记 null。预算的 40000 是编译器内部默认，没压预算就该看出来。轮数上限始终生效，80 就是这次跑实际停住的数。记 null 会把撞上限的原因藏起来。

为什么 passthrough 不忽略 `--max-turns`。这道限制在内核循环里，不在编译器里。忽略之后，对照的两边轮数不再是同一个上限。

为什么没写旗标时子进程 argv 仍带 `--max-turns 80`。`results.json` 里的数应当就是子进程收到的数。漏掉旗标，80 只是文件上的标签，和 `session.ts` 的默认可能以后对不上。

为什么不新增一种 Log entry。停住的事实已经在 `terminal {outcome:"max_turns"}` 和 `request_header` 的条数里。argv 继续不进 Log。

为什么报表不带 `maxTurns`。验收要的是 `results.json`。比率的口径不因这道上限改变，要对数字时直接看结果文件。

## Consequences

不传参的 run 现在可以走到 80 轮。提前 `stop` 的任务不受影响。会撞上限的任务多付最多 30 轮的模型和工具开销。子任务调用 `session.run` 时不传 `maxTurns`，因此用内核默认 80，不继承这次 CLI 旗标。非法值在父进程退出 2，不起任务。argv 和那句错误不进 Log。读一份没有 `maxTurns` 的 `results.json` 时按 80 计，报表输出不变。

## Testing

`pnpm check` 退出码 0（lint、tsc、分层、README、log manifest、337 个测试）。覆盖不传 `maxTurns` 时第 80 个 `request_header` 之后 `terminal.outcome` 为 `max_turns`、`--max-turns 3` 在编译器与 passthrough 下都第 3 轮终止、`abc` 与 `0` 退出 2、`bench run --max-turns 60` 的 argv 与 `results.json.maxTurns`、没写旗标时为 80。不打真网，不跑真机 bench。

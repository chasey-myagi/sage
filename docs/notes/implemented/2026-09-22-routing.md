# 阶段边界换模型

## Problem

中立 harness 可以在阶段边界换 provider，但缺一个不碰缓存账的接口。换型号的真实成本不在「再读一遍前缀」——那笔钱阶段边界本来就要付——而在跨模型的消息形状：别家的 thinking 块和 tool id 直接送过去会让请求失败。敏感数据也不能跟着最便宜的型号出境。

## Decision

路由策略只在编译器判定 `rebuild` 为 true 时调用。`sensitivePolicy` 按新视图里 tier 不是 none 的块的 access key 裁掉 provider，`costTierPolicy` 在剩下的 ladder 里选目录 input 价最低、且目录定得了价的型号。结果写在 `epochStart.model`，reason 追加到清单的 `epochDecision.reason`。

内核看到新型号，在 `view_epoch` 之前追加 `model_change {from, to, reason}`，reason 是 `route:` 加上策略给出的理由。然后切换 adapter 并用新型号再 `prepare`。找不到适配器就记 `terminal` error，不发请求。`view.head` 不改。`RunSummary.modelChanges` 等于这次 run 的 `model_change` 条数。

跨 provider 的规整是 `normalizeForApi`。OpenAI 丢掉 thinking，并把 `toolu_` id 改成 `call_` 加 sha256 前 24 位，tool_result 同步。Anthropic 丢掉没有 signature 的 thinking，其余原样。两个适配器编码前各调一次。

`apps/sage` 有两家 key 就装两个 adapter。默认策略是 `.env` / `secrets` 拒绝非默认 provider，再在允许的型号里选最便宜的。只有一家 key 时 ladder 只含这一家。

## Alternatives considered

为什么只在阶段边界换。阶段内前缀是冻结的，中途换模型等于主动砸掉还在命中的缓存，而且不等式已经把「值不值得重建」算过了。把切换绑在 rebuild 上，不多花一分缓存钱，也不用在阶段中途再开一条策略。路由若将来用模型判断，必须是主请求的前缀延长（E7）；这一版不用模型。

为什么敏感度看新视图而不是整段历史。淘汰成 none 的块已经不进这次请求，模型看不到那条路径。用整段历史会把已经省略的 `.env` 永远钉在禁令上，便宜型号再也回不来，也和「模型看见什么」对不上。新视图里仍是 line / summary / full 的块才算触碰。

为什么规整放 provider 不放内核。tool id 和 thinking 的形状是各家线上格式的事，内核只拥有 Log 和 View seam。放进内核就会让 core 认识 Anthropic 和 OpenAI 的 id 规则。规整是编码前的纯函数，Log 仍记模型可见的原文，线上字节可以由 provider 和 api 重放出来。

## Consequences

不做阶段中途换模型，不做能力探测，不做子 agent。目录之外的型号不参与 ladder。`view.head` 在切换时逐字节不变，工具 schema 仍由各适配器自己翻译。单 adapter 构造还在，内部收成 `adapters` 表。

## Testing

红灯时 `normalize.ts` 与 `routing/policy.ts` 无法加载（`ERR_MODULE_NOT_FOUND`），会话测试里 `modelChanges` 为 `undefined`，缺适配器的路径仍是 `done`。`pnpm check` 退出码 0（lint、tsc、分层、README、log manifest、210 个测试）。

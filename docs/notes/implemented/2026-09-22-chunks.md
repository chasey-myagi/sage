# 分块索引与确定性淘汰

## Problem

打分之前，有些历史不用模型也能判定作废：同一个路径后来又读过、失败的调用已经用同样的参数重试成功、或者预算已经装不下最旧的工具输出。这些块如果继续整段留在请求里，既占 token，又会在后面的轮次里反复进前缀。

## Decision

编译器把 passthrough 投影出来的历史切成块。一次 `tool_use` 加上它的 `tool_result` 是一块，id 为 `seq:<assistantSeq>#<toolUseId>`。纯文本的 user / assistant 消息各是一块，id 为 `seq:<seq>`。和工具调用写在同一条消息里的正文另成一块，排在这些工具块前面。只含 `tool_result` 的 user 消息不单独成块。工具块的 token 是 `count(rawInput) + count(结果正文)`。访问列表来自 `ctx.tools` 里同名工具的 `accesses(input)`，key 按字符串相等比较。

`canSplitAfter` 是共享边界谓词：user 消息之后不切，带 `tool_use` 的 assistant 之后不切，下一条是含 `tool_result` 的 user 也不切，其余可以切。淘汰只丢掉整块，不在工具交换中间切开。

每块只取第一个命中的 reason，顺序是：最近 `keepRecent` 个工具块（默认 6）为 `full` / `recent`；其后非错误工具块若盖住了本块的全部 access，则为 `none` / `superseded_by:<id>`（读或 search 被后来的 read、write、search 覆盖，写只被后来的写覆盖，id 取最后一个盖住它的块）；失败块的下一个工具块若同名且 input 深比较相等，则为 `none` / `retry_intermediate`；再从最旧的、仍为 full 的非近期工具块降到 `none` / `budget:oldest-first`，直到保留总量不超过申领单扣完后的剩余预算。user 与 assistant 正文永远是 `full` / `kept`。`used` 只加非 none 的块。仍超出的部分记入 `budget.overrun`。

档位 `none` 的工具块：`tool_use` 留在视图里，对应 `tool_result` 的 content 换成 `[omitted]`，`isError` 不变。清单 chunks 带上 id、tier、reason，以及块上的原始 token 估算。`rebuildFromLog` 按清单里的 none 块把同一处结果还原成 `[omitted]`。`ViewContext.tools` 是会话构造时传入的工具列表，passthrough 不读它。

## Alternatives considered

工具块以 `tool_use` 为单位，不以消息为单位。一条 assistant 消息里经常有两次调用。按消息成块，它们只能一起留或一起扔，后一次读无法单独覆盖前一次。按调用成块，结果仍然通过 `toolUseId` 配回原来的 `tool_use`，`assertPaired` 不用改。

oldest-first 是临时策略。预算不够时，本票没有打分器（#15），不能判断哪一块对当前问题更有用。最旧的非近期工具块先降，规则稳定、可重放，也和「近期块一律保留」接得上。等打分器接入，这条 reason 就该让位，而不是在这里再加启发式。

user 文本块永不因预算降档。用户原话是后面轮次的问题本身，丢掉它，模型看到的历史就换了题目。助手的纯文本回复同理，它不是可替换的工具输出。工具结果可以按 key 覆盖或换成 `[omitted]`；这两类正文没有对应的「后来的一份」。超预算时它们留在 `used` 里，差额记 overrun。

## Consequences

没有申领单、预算也装得下时，请求与 passthrough 逐字节相同。清单不再是「每条消息一块、reason `passthrough`」：工具结果消息并进工具块，id 变成 `seq:<assistantSeq>#<toolUseId>`。`tool-roundtrip` 第二轮从 `seq:0`、`seq:3`、`seq:4` 三块，变成 `seq:0`（kept）和 `seq:3#call_1`（recent）。`budget.used` 含申领单和淘汰后仍保留的块。

覆盖先于预算。旧块已经标成 `superseded_by` 之后，若更新的那份又因预算降到 none，两份都会离开视图。这是「每块只取第一个 reason」的结果，不在本票里回退。失败调用的 access 不覆盖旧块。一个块有多条 access 时，要全部被后来的块盖住才算 superseded。

本票会改前缀。`[omitted]` 写在历史中间，不在尾部。M2 阶段淘汰结果每轮可能变化，前缀稳定性由 #12 接入。留桩句式和 expand 是 #10，这里的占位只有 `[omitted]`。

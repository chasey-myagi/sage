# 打分器解析器提取首个 JSON 数组

## Problem

Issue #71 记录影子打分修复版 312 次调用里 17 次 `invalid-json`。其中 16 次 `shadow.raw` 是合法数组后面跟着解释，例如数组结束后另起一行写 `The candidates…`。解析器对整段回复做 `JSON.parse`，尾随文字就让这次判定作废。剩下 1 次是模型拒绝旁路指令、正文里没有 JSON，那种应当继续 fallback。

## Decision

去掉一层 json 围栏之后，从文本里第一个 `[` 或 `{` 起，按括号配对取出一个值。字符串内的括号不计入深度，反斜杠转义的引号也不结束字符串。这个值前后的文字都忽略。配不平，或取出的文本不是 JSON，才是 `invalid-json`。

已有规则不变：单个带 `id` 的对象包成一项，未知 id 丢弃并计数，空数组 `[]` 是全部保留，缺 `id` 或 tier 非法则整段失败。判定成功时，即使原文前后还有解释，也不算 fallback，不写 `raw`。

第一个 `[` 或 `{` 就是候选起点。这段配平之后若不是 JSON，不再往后找第二个值。

## Alternatives considered

不在第一个配平片段解析失败后继续扫描。真机的 16 次是数组在前、解释在后，第一个括号就是判定。继续往后找会把前面的 `{note}` 跳过，把一次畸形回复收成成功。

不从第一个 `[` 截到最后一个 `]`。`summary` 里的 `a[0]}` 会在字符串中的 `]` 被截断；解释里再出现 `]` 又会把尾随文字包进来。

不和 jev 共用解析器。jev 要的仍是 answers 对象，不是这个数组。

## Consequences

确定性淘汰、冻结、阶段决策和校准没改。`dropped` 仍不进 Log。没加依赖。成功且带解释的回复不再写 `manifest.scorer.raw` 或 `manifest.shadow.raw`。

解释出现在 JSON 之前，且自身有一段配平但非法的 `{...}` 或 `[...]` 时，这次仍是 `invalid-json`。括号只出现在字符串里，或出现在配平结束之后，不影响取出的值。

## Testing

`pnpm check` 退出码 0（lint、tsc、分层、README、log manifest、364 个测试）。新增三条：数组后跟解释解析出 1 项且无 fallback、无 `raw`；无 JSON 的拒绝仍是 `invalid-json` 且 `raw` 有原文；`summary` 为 `a[0]}` 时整段数组被取出，尾随文字里的 `]` 与 `}` 不计入。围栏、单对象、未知 id、空数组仍由既有测试覆盖。测试不打真网。

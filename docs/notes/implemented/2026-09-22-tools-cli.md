# 第一方工具与 one-shot CLI

## Problem

内核已经能跑 loop，但没有工具，模型看不见工作区，也没有一个命令能在真实目录里把一轮做完。Log 里因此还没有「这一轮为什么是这些块」的 passthrough 清单。

## Decision

`packages/tools` 提供 `read` / `write` / `edit` / `bash` / `grep` / `find` / `ls`。每个工具声明 `isReadOnly` / `isDestructive` / `isOpenWorld`，并用 `accesses(input)` 给出规范化绝对路径与 `read` | `write` | `search`。带路径的工具在 `path.resolve` 之后、`realpath` 之后各查一次，任一越出 cwd 就返回 `isError`，不读不写。

`read` 默认 2000 行、262144 字节，不返回半行。`bash` 输出超过 30000 字节时全文落到 `<cwd>/.sage/tool-output/<toolUseId>.txt`，结果保留头 20000 与尾 5000，通知行算在上限内。默认 `exec` 是 `child_process.spawn`（shell），只给可信环境；生产必须注入沙箱化 `exec`。本票不实现沙箱。

`apps/sage` 的 `createCodingSession` 用 `JsonlLogStore`、`passthroughView` 和这七个工具装配 `AgentSession`，并在每次 `view_compiled` 追加一条 `manifest`。`sage -p "任务"` 把 `RunSummary` 打成一行 JSON；`done` 退出 0，其它退出 1。

## Alternatives considered

bash 的 `accesses` 固定返回空。命令里的路径、重定向和命令替换没法静态看全。如果解析命令字符串来填路径，别名和 `$(...)` 会给出一份假的安全声明，只读并发池就会放行不该并行的调用。空列表让它永远不进那个池。

grep 先调 `rg`，找不到就逐文件跑正则。命中格式都是 `file:line: text`。不把 `rg` 写成硬依赖，是因为第一方工具不该在没有 ripgrep 的机器上直接不存在。也不去调系统 `grep`：BSD 和 GNU 的参数不一样。

CLI 自己解析 argv，不引入 minimist 或 commander。这一票的旗标只有 `--print` / `-p`、`--provider`、`--model`。`@sage/provider` 没有导出 catalog 表，默认型号按 `packages/provider/src/catalog.ts` 里该 provider 的第一条写在 CLI 里，测试对着源文件核对。

Node 的类型剥离跑不了参数属性，包内相对导入又写成 `.js`。启动脚本因此带上 `--experimental-transform-types`，并把缺失的 `.js` 指到同名 `.ts`。不改 core / provider 的导出。

## Consequences

bash 不会进入只读并发池。spill 文件在 `.sage/tool-output`，已加入 `.gitignore`；文件本身不是 Log entry，模型看见的预览和路径在 tool result 里，因此会进 Log。

默认 exec 没有沙箱。注入口是唯一的接缝。本票不做 TUI、权限审批、MCP 和压缩。

`manifest` 由 CLI 在 `view_compiled` 时追加，不由内核写。payload 带上 `budget: null`，因为直通视图没有预算，而 kind 校验要求这个字段存在。

## Testing

`pnpm check` 退出码 0。工具测试覆盖声明、realpath 双查、2000 行翻页、bash spill、注入 exec、以及 edit 的 0 次 / 2 次 / 1 次。`apps/sage/test/e2e.test.ts` 用 faux 适配器先 read 再 edit，工作区文件被改，Log 里 message / request_header / manifest 都在，每条 manifest 的 chunk reason 都是 `passthrough`。

真机验收没有跑：当前环境没有 `ANTHROPIC_API_KEY` 或 `OPENAI_API_KEY`。

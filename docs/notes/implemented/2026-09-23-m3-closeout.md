# M3 收口：默认梯子、子任务预设、accesses 准入、子 usage

## Problem

M3 三张票合并时留下四处口径：

1. CLI 默认路由梯子取已装配 provider 的全部型号里最便宜的。两家 key 都在时，阶段重开会切到 `gpt-5.4-mini`。
2. 子任务没有带 frontmatter 的 `.md` 预设，也没有用户级加项目级两层发现。
3. 并行池只认调用方写的 `readOnly: true`，不看 `accesses` 冲突。
4. 子会话 usage 只在父 tool_result 的返回值 details 里，`runHealth` 读不到，口径未定。

## Decision

`defaultRoutePolicy` 的梯子默认是这次输入的当前型号。阶段重开因此不换型号。`--ladder provider/model,provider/model` 才把多档交给 `costTierPolicy({ pick: "cheapest-allowed" })`。`.env` / `secrets` 仍然从这张显式梯子里拿掉非 home provider。

`loadPresets({ cwd, home? })` 读 `<cwd>/.sage/subtasks/*.md` 和 `<home>/.sage/subtasks/*.md`。名字是文件名 stem，项目文件整份盖住同名用户文件。frontmatter 只解析 `name` / `budget` / `readOnly` / `model`（`provider/model`），不加依赖。`name` 不改注册名。正文是 query 模板，`{{args.xxx}}` 在 `spawn_subtask({ preset, args })` 时替换，缺的参数变成空串。调用里写明的 query、budget、readOnly、model 盖住预设。CLI 把 `homedir()` 传进会话；测试不传 home，就不会读到开发者自己的预设。

`spawn_subtasks` 在全部 `readOnly: true` 时放行。否则两两看 `accesses`：同一 key 上任一方是 write 即冲突；只读任务的 accesses 当空；没声明且不是只读，视为未知写，和任何其他任务冲突，key 记为 `unknown`。冲突整单拒绝，正文含 `(taskA, taskB, key)`，任务名用 query。声明了空数组则不是未知写。

内核在用户消息 entry 上写 `details.toolResults`（`toolUseId` / `name` / execute 的 details），不写进模型可见的 tool_result 块。`runHealth` 从这里汇总 `spawn_subtask` 与 `spawn_subtasks` 的子 usage，得到 `subtasks: { count, tokens }`。`tokens`、`cacheHitRatio`、`expandRate` 仍只算父会话 assistant usage 和最后一条 manifest。

## Alternatives considered

默认梯子继续用全目录、只在文档里劝人传参。两家 key 是正常安装，第一次重开就会换型号，劝告挡不住。把「只含当前型号」写进默认，跨型号留成显式梯子。

子任务预设用 YAML 库。frontmatter 只有四个键，自己切 `---` 和 `key: value` 就够，不必加依赖。

并行池继续只认 `readOnly`，把 accesses 留到以后。S2 要的是同一份资源声明决定能不能并发。只读仍是快路径；有声明的写者只要 key 不撞就能并行。没声明的写不能假装自己不碰任何东西，所以当成未知写整单拒绝。

子 usage 加进父 `RunSummary.usage` 或父 token 总量。那会让缓存命中率和 expand 率混进子会话，基准层拿父总量去除时口径就变了。子用量单独放在 `health.subtasks`，主指标不动。

## Consequences

不改编译器、打分器、provider 和 tools 包。core 按工具名识别那两种 tool result，因为 usage 已经写在父 Log 里，健康度不能再去问插件。

回放夹具里的 `terminal.health` 补上全零的 `subtasks`。没派子任务的 run 也带这个对象。

本票不合并。跨型号、预设和冲突对都要调用方显式给出；内核不会从工具的 `accesses()` 反推子任务声明。

## Testing

`pnpm check` 是合并前的闸门。红灯时：两家 adapter 的阶段重开 `modelChanges` 为 1 且选中 `gpt-5.4-mini`；`loadPresets` 模块不存在；同一 key 的两个写被拒绝，但文案仍是 “Parallel pool only accepts read-only subtasks.”；`health.subtasks` 为 `undefined`。

# M1 收口：内核落 manifest、execute 带 toolUseId、provider 导出 catalog

## Problem

PR #23（issue #6 的实现报告里的三条拍板）留下三处接口缺口：

1. `manifest` 由 CLI 在 `view_compiled` 里追加，内核 `AgentSession` 不写。清单是「这一轮为什么发出这些」的唯一记录，靠 app 自觉就违反 L4。
2. `HarnessTool.execute` 的上下文没有 `toolUseId`。bash 的 spill 文件名靠 session 的 `around` 把调用 id 绑进 AsyncLocalStorage；直接调用 `execute` 时退回随机 UUID。
3. `@sage/provider` 不导出 catalog。CLI 把 anthropic / openai 的默认型号按源文件第一条写成 `claude-sonnet-4-5` 和 `gpt-5`，测试读 `catalog.ts` 源文件核对。

## Decision

内核在追加 `request_header` 之后、`adapter.stream` 之前追加 `{ kind: "manifest", payload: view.manifest }`。`manifest` 的校验按 `Manifest` 收紧：`epoch` / `turn` 为有限数字，`claims` / `chunks` / `anomalies` 为数组；`budget` 可选，出现时必须是有限数字。直通视图没有预算，因此不再要求这个字段存在。

`execute` 的 ctx 增加必填 `toolUseId: string`。session 的工具管线把 `call.id` 传进去。bash 用 `ctx.toolUseId` 命名 `<cwd>/.sage/tool-output/<toolUseId>.txt`，删掉 AsyncLocalStorage 与 `withToolUseId`。

`@sage/provider` 导出 `listModels(provider)`、`defaultModel(provider)`（该 provider 目录第一条）和 `CatalogEntry`。目录五条数据不变。CLI 不带 `--model` 时用 `defaultModel(provider).model`。`createCodingSession` 不再挂 `view_compiled` 补写 manifest，也不再 `around` 绑定 tool id。

## Alternatives considered

manifest 不能留给 app 写。`view_compiled` 是观察钩子：抛错被吞掉，run 继续，清单就丢了。钩子发生在 `request_header` 之前，写出来的顺序是 manifest 夹在用户消息和信封中间，不是紧跟它解释的那封请求。CLI 为了通过旧校验还要补 `budget: null`，并丢掉 `anomalies`，于是同一份清单有两种形状。第二个调用方（回放、测试、以后的 TUI）只要忘了挂同一个钩子，Log 里就没有这份记录。L4 要求进入模型请求的内容能从 Log 重建，L5 要求同一事实只有一个来源。请求信封已经由内核写，清单是那封请求的理由，必须同一只手写上。

spill 文件名也不该走 AsyncLocalStorage。id 是这次 `tool_use` 的事实，调用 `execute` 的人手里就有。藏在异步上下文里，直接调用拿不到，测试还得先包一层绑定。

默认型号不该抄进 CLI。目录改一行，CLI 和读源文件的测试都要跟着改，单一来源就不成立。

## Consequences

Log 路径为 `message(user) → request_header → manifest → message(assistant) → …`。payload 就是当时的 `view.manifest`。直通时没有 `budget` 字段，`anomalies` 在。

回放的 `session.jsonl` 在每条 `request_header` 后插入一条 manifest。tool-roundtrip 第二轮期望清单里，助手消息和工具结果的 chunk id 从 `seq:2` / `seq:3` 变成 `seq:3` / `seq:4`，因为第一轮插入的 manifest 占了一个 seq。比较 Log 时把 manifest 里的 entry id 收成 `seq:N`，否则每次回放的 uuid 对不上。

`defaultModel` 对目录里没有的 provider 抛错。已知的 anthropic / openai 仍取第一条。`--model` 仍然覆盖。

本票不改 manifest 的内部结构，也不做 dist 构建布局。

## Testing

`pnpm check` 退出码 0（lint、tsc、分层、README、log manifest、120 个测试）。红灯时 7 个失败：Log 里没有 manifest、execute 收到的 `toolUseId` 是 `undefined`、spill 文件名仍是随机 uuid、`listModels` / `defaultModel` 不是函数、没有 `anomalies` 且缺少 `budget` 的 payload 被当时的校验拒绝。
